PASOS PARA COMPARTIR EL PROYECTO CON TUNNELMOLE (WINDOWS/POWERSHELL)

Objetivo:
- Compartir un enlace publico del frontend para pruebas reales desde internet.
- Mantener comunicacion estable frontend <-> backend (REST y WebSocket).

==================================================
1) CONFIGURACION MINIMA
==================================================

Archivo: .env.local

NEXT_PUBLIC_API_URL=/api
BACKEND_INTERNAL_URL=http://localhost:8080

Notas:
- `NEXT_PUBLIC_API_URL=/api` mantiene llamadas same-origin y evita CORS en flujo normal.
- `BACKEND_INTERNAL_URL` apunta al backend local para los rewrites de Next.js.

==================================================
2) ARRANQUE RAPIDO (RECOMENDADO)
==================================================

Desde la raiz del proyecto:

cd C:\Users\Cristian\Downloads\educearch-frontend-development

Modo desarrollo compartido:
cmd /c npm run share:stack

Modo produccion local + tunnel:
cmd /c npm run share:stack:prod

Modo produccion + tunnel backend para WebSocket:
cmd /c npm run share:stack:prod:ws

El script:
- levanta backend y frontend (si no estaban levantados),
- genera URL publica de tunnelmole para frontend,
- y en modo `:ws` tambien genera tunnel de backend e inyecta `NEXT_PUBLIC_WS_URL`.

==================================================
3) ARRANQUE MANUAL (ALTERNATIVA)
==================================================

Terminal 1:
cd C:\Users\Cristian\Downloads\educearch-frontend-development\backend
mvn spring-boot:run

Terminal 2:
cd C:\Users\Cristian\Downloads\educearch-frontend-development
cmd /c npm run build
cmd /c npm run start:public

==================================================
4) CREAR ENLACE PUBLICO DEL FRONTEND
==================================================

Terminal 3:

cd C:\Users\Cristian\Downloads\educearch-frontend-development
cmd /c npm run share:frontend

Comparte la URL generada:
https://xxxxx.tunnelmole.net

==================================================
5) FALLBACK PARA WEBSOCKET (SI CHAT FALLA)
==================================================

Si REST funciona pero chat en tiempo real no conecta:

Terminal 4:
cmd /c npm run share:backend

Luego, en `.env.local`, agrega:

NEXT_PUBLIC_WS_URL=wss://<backend-subdominio>.tunnelmole.net/ws-native

Reinicia frontend.

==================================================
6) CHECKLIST DE PRUEBA
==================================================

1. Abrir enlace publico desde al menos 2 dispositivos.
2. Registrar/login usuarios distintos.
3. Verificar peticiones `/api/...` en Network.
4. Verificar WebSocket `/ws-native` si usas chat.
5. Confirmar que no hay errores CORS/Mixed Content.
