RESUMEN DE APIS EXTERNAS Y COMUNICACION EN ESTE PROYECTO
========================================================

1) COMO SE CONECTA EL FRONTEND
------------------------------
- El frontend NO llama normalmente a APIs externas directo.
- El frontend llama a rutas internas /api/* y Next.js reescribe al backend Spring Boot.

Base y rewrite:
- Frontend env: .env.local -> NEXT_PUBLIC_API_URL=/api
- Cliente HTTP: lib/api-client.ts (usa process.env.NEXT_PUBLIC_API_URL o /api)
- Rewrite Next: next.config.mjs
  source: /api/:path*
  destination: http://localhost:8080/api/:path*

Flujo general:
Frontend (3000) -> /api/... (Next rewrite) -> Backend (8080) -> APIs externas


2) ENDPOINTS INTERNOS CLAVE (LOS QUE USA EL FRONT)
---------------------------------------------------
A) Busqueda
- POST /api/search/execute
  Uso: busqueda principal (PubMed via backend).
  Archivo: backend/src/main/java/com/uci/competencia/controller/api/SearchController.java

- GET /api/search/mesh/suggestions?term=...
  Uso: sugerencias MeSH.
  Archivo: SearchController.java

- POST /api/search/external-fallback
  Uso: fallback externo agregado por backend (PubMed + Europe PMC + ClinicalTrials).
  Archivo: SearchController.java
  DTO request: backend/src/main/java/com/uci/competencia/model/dto/request/ExternalHealthSearchRequestDTO.java
  Campos request:
    queryText, terms[], yearFrom, yearTo, studyTypes[], language,
    hasFullText, minSampleSize, maxResults

- GET /api/search/history?page=1&limit=10
- PUT /api/search/{searchId}
- DELETE /api/search/{searchId}
- GET /api/search/sessions/{sessionId}

B) Verificacion
- POST /api/verify/claim
  Uso: verifica claim o URL.
  Archivo: backend/src/main/java/com/uci/competencia/controller/api/VerificationController.java
  DTO request: backend/src/main/java/com/uci/competencia/model/dto/request/VerificationRequestDTO.java
  Campos request:
    claimText, sourceUrl, context, priority

- GET /api/verify/result/{verificationId}
- GET /api/verify/history?page=1&limit=10

C) Admin (diagnostico de externas)
- POST /api/admin/external-apis/check
  Uso: testea conectividad y respuesta de proveedores externos.
  Archivo: backend/src/main/java/com/uci/competencia/controller/api/AdminController.java

- POST /api/admin/test-pubmed
  Uso: prueba puntual de PubMed.

4) DONDE ESTA IMPLEMENTADO EL ACCESO A EXTERNAS
------------------------------------------------
Frontend (fallback controlado):
- lib/health-sources.ts
  - intenta backend proxy: /search/external-fallback
  - si falla, puede consultar proveedores externos directos
  - cache local de resultados/verificacion

Backend (agregador principal de externas):
- backend/src/main/java/com/uci/competencia/service/external/HealthSearchProxyServiceImpl.java
  - PubMed
  - Europe PMC
  - ClinicalTrials
  - retry + timeout + cache

Backend PubMed/MeSH dedicado:
- backend/src/main/java/com/uci/competencia/service/external/PubMedApiServiceImpl.java

Backend OpenAI:
- backend/src/main/java/com/uci/competencia/service/external/OpenAIServiceImpl.java

6) COMO CONSUMIR (EJEMPLOS RAPIDOS)
-----------------------------------
Nota: endpoints protegidos requieren JWT Bearer token.

1) Login (obtener token)
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"tu_usuario","password":"tu_password"}'

2) Fallback externo agregado (search)
curl -X POST http://localhost:8080/api/search/external-fallback \
  -H "Authorization: Bearer TU_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "queryText":"diabetes type 2 metformin",
    "yearFrom":2019,
    "yearTo":2026,
    "studyTypes":["systematic_review","meta_analysis"],
    "language":"eng",
    "hasFullText":true,
    "maxResults":10
  }'

3) Verificar claim/URL
curl -X POST http://localhost:8080/api/verify/claim \
  -H "Authorization: Bearer TU_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "claimText":"Metformin reduces cardiovascular mortality in type 2 diabetes",
    "sourceUrl":"https://ejemplo.com/articulo"
  }'

4) Diagnostico admin de APIs externas
curl -X POST http://localhost:8080/api/admin/external-apis/check \
  -H "Authorization: Bearer TU_TOKEN_ADMIN" \
  -H "Content-Type: application/json" \
  -d '{"queryText":"diabetes"}'


7) RECOMENDACION PRACTICA DE INTEGRACION
----------------------------------------
- Para este proyecto, integra siempre por /api/* (backend), no pegues al frontend directo
  contra OpenAI/PubMed/EuropePMC/ClinicalTrials en produccion.
- Beneficios: seguridad de llaves, control de rate limit, logs, cache y filtros centralizados.
